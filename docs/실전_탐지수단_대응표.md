# 실전 탐지 수단과 프로젝트 합성 센서 대응표

`data_sources/synthetic_sensors.py`가 합성으로 만들어내는 신호들이, 실제로는 어떤 군사 탐지 수단을 개념적으로 흉내낸 것인지 정리한 문서. 면접에서 "왜 레이더·열화상·SIGINT를 합성했나요?"라는 질문에 답할 근거 자료.

## 대응표

| 실전 탐지 수단 | 원리 | 프로젝트에서 대응되는 것 |
|---|---|---|
| **1차 감시 레이더(Primary Radar)** | 전파를 쏘고 반사파(에코)를 받아 위치 파악 — 상대방이 응답 안 해도 잡힘 (트랜스폰더 불필요) | `synthetic_sensors.py`의 "레이더 반사(RCS)" |
| **2차 감시 레이더 / IFF** | 아군기에게 암호 질의를 보내고, 정상 응답이 오면 아군으로 확인 (무응답/오응답 시 의심) | `fusion/identification.py` — 다만 실제 IFF 데이터가 없어 FRIEND/HOSTILE은 판정 못 하고 NEUTRAL/UNKNOWN까지만 구현 (한계를 정직하게 문서화함) |
| **AWACS(공중조기경보통제기)** | 높은 고도에서 넓은 범위를 감시하는 레이더 탑재 항공기 — 지상 레이더의 지평선 사각지대 보완 | 프로젝트에 없음 (향후 확장 후보) |
| **IRST(적외선 탐색추적)** | 엔진열 등 열 신호를 광학적으로 포착 — 레이더 회피 기체에 특히 유용 | `synthetic_sensors.py`의 "열화상 신호" |
| **ELINT/SIGINT(전자정보 수집)** | 상대방 레이더·통신 전파 자체를 감청해서 존재를 역추적 | `synthetic_sensors.py`의 "SIGINT 신호 포착" |
| **위성 기반 적외선 조기경보** | 로켓엔진 연소 열원을 우주에서 감시 (주로 탄도미사일 발사 탐지용) | 프로젝트에 없음 (Phase 6 후보로 추가) |

## 왜 이 대응관계가 중요한가

전투기가 ADS-B(민간 트랜스폰더)를 꺼도, **1차 감시 레이더는 여전히 잡습니다** — 전파를 쏘고 반사파를 받는 방식이라 상대방의 협조가 필요 없기 때문. 다만 스텔스 기체는 이 반사파(RCS) 자체를 최소화하도록 설계되어서, 진짜 문제는 "협조를 안 해서"가 아니라 **"반사파가 너무 작아서 레이더가 못 잡는" 경우**.

이 프로젝트가 OpenSky(민간 협조식 트랜스폰더 데이터)로는 못 잡는 한계를 갖는 이유가 정확히 여기 있고, 실전에서는 1차 레이더 + IRST + SIGINT를 다중 융합해서 이 문제를 보완함 — 이게 `synthetic_sensors.py`가 여러 센서를 동시에 합성하는 구조로 설계된 이유.

## 위성 조기경보의 실제 판단 구조 (참고)

영화에서 흔히 보는 "발사체 열원 감지 → 미사일로 추정" 장면은 실제 원리와 정확히 일치함:

1. **위성이 실제로 감지하는 것**: 로켓엔진 연소의 적외선 열원뿐. 미사일의 형태·종류는 직접 안 보임.
2. **"미사일이다"라는 판단은 관측값이 아니라 맥락(context)에서 나옴**:
   - 위치: 알려진 발사장/발사대 좌표와 일치하거나 근접
   - 열 신호 패턴: 일반 화재와 다른 급격한 상승 곡선·강도
   - 타이밍/정황: 다른 정찰 정보와의 교차 검증

이 구조(관측 데이터 + 위치 맥락 + 패턴 분석 = 추론)는 프로젝트의 `geofence.py`(보호구역 근접도) + `threat_scoring.py`(여러 신호 종합)가 흉내내는 것과 동일한 원리.

## "탐지"와 "추적"은 다른 임무다 (2026-08-10 추가)

넓은 범위를 느리게 보는 수단(위성)과, 좁은 범위를 빠르게 보는 수단(레이더·소나)은 역할이 나뉜다. 카메라 렌즈 원리상 화질을 올리면 시야가 좁아지고, 시야를 넓히면 화질이 떨어지기 때문에 "지구 전체를 실시간 정밀 감시하는 위성"은 존재할 수 없다.

| 단계 | 담당 | 예시 |
|---|---|---|
| **탐지 (Detection)** — "뭔가 있다/사라졌다"를 발견 | 정지궤도 적외선 위성, 저궤도 정찰위성 | 로켓 발사 열원 포착, 잠수함이 항구에서 사라진 걸 확인 |
| **추적 (Tracking)** — 이후 실시간·연속 위치 파악 | 레이더(지상/함선/항공기), 소나 | 배틀쉽 영화의 함선 레이더 네모박스, 대잠초계기의 잠수함 추적 |

**잠수함 사례**: 잠항하면 광학·적외선 위성으로는 물속을 못 봄. 위성이 실제로 할 수 있는 건 "이전 촬영 때 있던 잠수함이 이번엔 없다" → 출항을 **추론**하는 것뿐. 실제 이동 경로는 소나·대잠초계기 등 완전히 다른 계열의 센서가 담당 (탐지와 추적의 담당 주체가 아예 바뀜).

**위성 여러 대로 감시 간격을 줄이는 원리**: 재방문 간격 ≈ 궤도 주기 ÷ 같은 궤도면의 위성 수. 실제로 Planet Labs 같은 상업위성 회사는 소형위성 130기 이상을 띄워 지구 전역을 거의 매일 촬영하는 걸 실현함. "하나의 느린 소스를 빠르게" 만들기보다 "여러 소스를 병렬로" 쓰는 전략.

**한계**: 이 원리를 OpenSky 같은 공개 API에 그대로 적용할 순 없음 — 위성은 물리적으로 다른 지점에서 관측해 "새로운 관측"이 생기지만, 같은 API 계정을 여러 개 만든다고 항공기가 신호를 더 자주 보내는 건 아니라서 실질적 개선이 안 됨. 계정을 늘려서 해결되는 문제와, 물리적으로 다른 센서를 늘려야 해결되는 문제는 구분해야 함.

## 능동(Active) vs 수동(Passive) 센서 — SOSUS에서 파생된 구분

| | 능동(Active) | 수동(Passive) |
|---|---|---|
| 방식 | 전파/음파를 직접 쏘고 반사를 받음 | 그냥 듣기만 함, 아무것도 안 쏨 |
| 예시 | 일반 레이더, 능동 소나 | SOSUS(고정 수중청음망), SIGINT(전파 감청) |
| 장점 | 정확한 거리·위치 계산 가능 | 자기 위치가 안 들킴 |
| 단점 | 신호를 쏘는 순간 자기 위치를 노출 | 방향은 알아도 정확한 거리는 추정만 가능 (원리상 능동 없이는 거리 확정 불가) |

프로젝트의 `synthetic_sensors.py` 중 "SIGINT 신호 포착"은 수동 탐지, "레이더 반사(RCS)"는 능동 탐지를 흉내낸 것 — 능동은 정확하지만 들킬 위험, 수동은 안 들키지만 부정확하다는 트레이드오프 때문에 둘을 같이 씀.

SOSUS는 위성처럼 "가끔 지나가며 보는" 방식과 정반대로 간격 없이 항상 켜져 있어, 폴링 간격으로 인한 탐지 실패 문제 자체가 없음. 대신 설치 비용이 매우 크고 위치를 못 옮김.

## 전자전(EW)과 이 프로젝트의 숨겨진 약점

전자전은 3갈래로 나뉨: 전자지원(ES, 상대 신호 감청 — 오늘 만든 SIGINT 센서), 전자공격(EA, 상대 센서 방해·기만), 전자보호(EP, 내 센서 방어).

EA(재밍)의 두 방식:
- **잡음 재밍**: 특정 주파수에 강한 잡음을 쏟아부어 진짜 신호를 못 알아보게 함
- **기만 재밍(디코이)**: 가짜 신호를 대량으로 흘려 진짜보다 훨씬 많은 물체가 있는 것처럼 보이게 함

**발견한 프로젝트의 약점**: `ANALYST_REVIEW_THRESHOLD`(55점) 이상이면 매번 사람이 승인/거부를 판단하는 구조인데, 만약 누군가 가짜 고위협 신호를 대량으로 흘려보내면(디코이 포화 공격) 진짜 위협 하나를 가짜 알림 수십 개 속에 파묻어 분석관을 지치게 만들 수 있음. 지금 설계는 이 공격에 방어책이 없음 — 당장 고칠 필요는 없지만 "이 시스템의 한계는?"이라는 질문에 답할 수 있는 통찰.

## 칼만 필터 — 불완전한 관측으로 진짜 위치 추정하기

핵심 2단계 반복:
1. **예측(Predict)**: 마지막 위치+속도로 미루어 "지금쯤 여기 있을 것"이라 예상
2. **보정(Update)**: 새 관측값이 들어오면, 예측과 관측 중 더 믿을 만한 쪽에 가중치를 줘서 최종 추정치 계산

관측이 부정확하거나(재밍 등으로 튄 값) 끊기더라도(폴링 공백 구간), 자동으로 "이번 관측은 덜 믿고 예측을 신뢰"하는 방향으로 조정되어 그럴듯한 경로를 유지함.

**프로젝트 연결점**:
- Phase 4(경로 예측) — 계획했던 "선형 외삽"보다 훨씬 정교한 버전. 폴링 사이 놓친 구간도 자연스럽게 메움
- 미뤄뒀던 "신뢰도 가중 센서 융합" — "더 믿을 만한 쪽에 가중치"가 정확히 그 개념의 수학적 formalization. 두 아이디어가 사실 같은 문제였음
- 재밍 대응 — 이상치(재밍으로 튄 값)를 자동으로 덜 신뢰하도록 설계 가능해, 디코이 포화 공격에도 부분적 완화책이 됨

## 센서-사격체 분리(Sensor-Shooter Separation)와 TMA — 사용자 아이디어 검증

**아이디어**: 무인 소형 잠수체가 먼저 진입해 수동으로 방향만 파악 → 필요한 순간에만 능동(핑)으로 정확한 거리 확정 → 그 좌표를 뒤따르는 무장 잠수함에 전달해 공격.

**실제 교리와의 일치**: 이건 실제 "센서-사격체 분리" 개념과 상당히 유사함 — 탐지 역할(손실 감수 가능한 무인체)과 사격 역할(끝까지 은닉하는 무장 잠수함)을 분리하는 게 핵심 철학. 수동으로 방향만 알아내고 능동으로 거리를 확정하는 순서도 원리적으로 정확함 (수동 소나는 원리상 방향만 알 수 있고, 정확한 거리는 능동 없이는 확정 불가).

**현실적 난점 2가지**:
1. 능동 핑을 쏘는 순간 무인체 위치가 노출되고, 적도 탐지당했음을 인지 → 회피기동 개시. 전체 과정(핑→좌표계산→전달→공격)이 적이 회피하기 전에 끝나야 함 — 시간 싸움
2. 수중 통신(음향 모뎀)은 라디오파 대비 대역폭이 극히 낮고 느림 → 좌표 전달 지연 시 낡은 정보가 될 위험

**실전 대안 — TMA(Target Motion Analysis)**: 능동을 아예 안 쓰고, 잠수함 자신이 여러 번 방향을 바꿔가며 수동으로만 여러 각도에서 방위를 측정 → 그 각도들의 교차점으로 상대 위치·속도·항로를 역산. 능동을 안 쓰니 안 들키지만 시간이 걸리고 계산이 복잡함. TMA는 여러 시점의 부정확한 방위 관측값으로 "가장 그럴듯한 상대 위치·속도"를 추정하는 문제라 칼만 필터(또는 최소자승 추정법)로 푸는 게 표준.

**결론**: 사용자 아이디어(무인체+능동)는 빠르고 확실하지만 들키는 방식, TMA는 느리지만 안 들키는 방식 — "빠름 vs 안 들킴" 트레이드오프가 여기서도 반복됨.
